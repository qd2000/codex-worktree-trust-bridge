## Confirmed findings versus uncertainty

1. **Confirmed lifecycle defect:** the old launcher only started a child and
   waited. A bounded control test compiled the pinned v0.2.1 launcher and used a
   harmless fake runtime. Killing that launcher left its fake child alive. The
   outer test-owned job then removed the residual; no production PID was used.
2. **Confirmed unbounded observation path:** v0.2.1 scanned full descendant trees
   with `TrueCondition` on an STA PowerShell runtime. Whole UIA result sets and
   broad provider traversal were not isolated by a resource-owning supervisor.
   This is an identified high-risk path, **not proof of the entire native/UIA
   leakage mechanism** that caused historical multi-GiB private memory.
3. **Confirmed health gap:** a recent reconcile and a plausible process pair did
   not establish UIA availability, bounded resource use, or artifact identity.
4. **Confirmed target-identity compatibility:** the observed full-trust Codex
   executable had no token package identity, although it belonged to a current-
   user registered Store package. The new native registration/Store-origin/exact-
   path check accepted that real executable in a read-only test. It does not
   accept process-name or WindowsApps-prefix lookalikes.

## Implemented core changes

`Native.cs` creates a suspended process **already in** a kill-on-close Job using
`PROC_THREAD_ATTRIBUTE_JOB_LIST`. It uses owned handles, creation identities,
bounded process-ID queries and explicit empty-job cleanup verification. There
is no create-then-assign gap, process-name termination, or unsafe fallback.

The launcher owns the runtime and descendants, uses a per-user/config mutex,
rejects duplicates, and atomically publishes startup hashes and process birth
receipts. The long-lived authority no longer loads UIAutomationClient.

The MTA UI worker has bounded root/window/control/depth/token/diagnostic/message
limits, scoped tree walking and ancestry checks, fresh dialog/control/path
validation, and single-use action tokens. It holds no UIA objects across requests
or threads and registers no event subscriptions. A real controlled test caught
a filtered-view subtree escape; the boundary condition and ancestry checks were
fixed rather than relaxing the traversal budget.

The supervisor uses same-user bounded pipe frames and exact worker peer PID,
provisional 256/384 MiB soft/hard job limits, an end-to-end request deadline,
explicit resource/degraded/circuit-open states, and at most three failures before
latching. No verified target window releases the UI worker without discarding
uncertain intents. There is no forced GC, working-set trimming, periodic whole-
bridge restart, or unbounded worker restart loop.

Only the authority writes configuration. It keeps deny/path/Git policy, backups,
mutex and atomic replacement; detects preimage conflicts; and validates UI at
the config commit boundary after acquiring the mutex. A persistent bounded
action ledger is written before invocation, so a lost response cannot become an
automatic replay after worker recovery or state reload. Status now requires
fresh identity/manifest/UI/resource evidence, not just a reconcile log. A failed
UI validation no longer adds a path to the shared reconciliation set; only a
verified successful configuration write commits that managed-path transition.

## Bounded Git/reconcile checkpoint

The authority no longer calls unbounded `WaitForExit` or `ReadToEndAsync` for
Git. Each Git command is created atomically inside a kill-on-close Job, inherits
only standard handles, writes to bounded temporary files and has explicit time,
cleanup, output, memory and process-count limits. Reconcile has an end-to-end
deadline plus directory/repository/worktree/command budgets. Partial discovery
never replaces the previous managed state.

The focused isolated run passed twelve cases: normal discovery, hanging Git and
descendant cleanup, stdout/stderr overflow, non-zero exit, invalid UTF-8,
malformed output, worktree/command/repository/directory limits, and 100 repeated
reconciles. It recorded 100 resource samples; authority Private Bytes peaked
around 114 MiB, handles peaked at 507, and both measured slopes were negative.
This focused result is not the replacement candidate suite or gray result.

## First fleet rollout failure and replacement fix

The first frozen manifest
`7984b09e8033be0489a59b7690528d66e5b598b6786d895ef7c6c7bbe20b1308`
passed the QDSPC gray gate. Local preserved broad roots `C:\PROJECT` and
`D:\PROJECT`; its historical backup tree contained 55 `.git` markers, including
markers that no longer described repositories. The candidate treated
`git rev-parse --git-common-dir` exit 128 as critical, so initial reconcile stayed
degraded and the installer rolled back successfully. Expansion stopped before
T113.

The replacement implementation uses C-locale Git diagnostics and skips only a
plain exit-128 `fatal: not a git repository` result. Timeouts, output/UTF-8/
cleanup/start failures, malformed output, and all other exits remain critical.
The default reconcile deadline is raised from 30 to 120 seconds while all
per-command, process, output, memory and total budgets remain bounded.

A read-only isolated probe against Local's actual roots completed successfully
without UI or configuration writes: 87.279 seconds, 2,437 directories, 55 marker
candidates, 49 valid worktrees and 191 bounded Git commands. Production Local
configuration and its restored v0.2.1 bridge were not mutated by that probe.

The first replacement full-suite run then preserved another real failure: a
rollback directory rename hit a transient Windows sharing lock after the exact
runtime tree had exited. Cleanup still completed. The maintenance implementation
now retries only Win32 5/32/33 while source exists and destination is absent; a
dedicated lock fixture exercised the retry for over one second, and the complete
maintenance lifecycle subsequently passed. The failed suite receipt remains in
`.artifacts` and is not reclassified as a pass.
