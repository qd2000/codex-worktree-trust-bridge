# v0.2.2 acceptance contract (frozen before implementation)

Status: **NOT ACCEPTED / NOT RELEASED**. Baseline: v0.2.1,
`4694347dbbba52d4daa097c14198caf84ff2a718`.

This contract separates source completion, candidate acceptance, release,
per-host deployment, and sustained validation. Passing a short test or restarting
the bridge is not sustained acceptance. Any change to a threshold must be explicit
and justified by new measurements; a failing run must not be relabeled a pass.

## Scope and invariants

Only this auxiliary bridge may change. Do not update DevSpace, Codex, Node,
Windows, other projects, or periodic monitoring. Develop on the designated source
host in an isolated worktree. Preserve existing changes and each host's policy.
Use only the existing repository remote. Never replace an existing release tag.

Keep exact-path authorization, rejection of reparse points and out-of-root paths,
Git registration in git-only mode, unique validated Trust/Cancel controls,
configuration mutex, backups, atomic replacement, and preservation of unrelated
configuration. Ambiguous identity, dialog, path, or action outcome fails closed.
Tests must not click unrelated business dialogs or write the real Codex config.

## Resource experiments

Record wall-clock and monotonic elapsed time, version/source hashes, workload,
PID/start time/parent/executable identity, Private Bytes, Working Set, handles,
scan/reconcile counts, and available managed-heap metrics. Missing metrics are
unknown, not zero. Preserve raw multi-point JSONL and machine-readable summaries.

Separate (1) UIA observation without invoking actions, (2) Git/reconciliation
with UIA disabled and an isolated profile, and (3) start/stop/crash lifecycle.
Compare old and new implementations under the same controlled workload. Label an
extracted/instrumented scan accurately; it is not the unmodified full runtime.

Old-version experiments: at most five minutes per experiment, 256 MiB Private
Bytes per observer, 512 MiB aggregate test-process guard, and a finite cleanup
deadline. Never reproduce the historical tens-of-GiB condition on the host.
Abort on budget, timeout, or identity uncertainty and record the reason.

Initial proposed UI-worker budget: 256 MiB soft / 384 MiB hard, checked by an
external owning process, with at most ten seconds per UI request. These are
containment limits, not leak-proof claims. Historical normal freshly-started
PowerShell observations were about 70-86 MiB; candidate warm measurements must
confirm adequate headroom before adoption. No forced GC, working-set trimming,
or periodic restart of the whole bridge may be used to pass.

Bound element retention, scan depth/count, candidate count, message sizes,
subscriptions, cooldowns, and diagnostic history. UIA objects stay on their
documented automation thread; do not invent AutomationElement.Dispose or use
indiscriminate COM release. Worker isolation is a fallback for uncertain provider
behavior, not proof of the complete leak mechanism.

## Required functional and fault tests

- Existing offline policy/configuration and silent-start/Git-child tests pass in
  isolated test profiles. Invalid/denied/reparse paths, ambiguous and changed
  dialogs, and stale action tokens must not be approved.
- Concurrent/double launch, ordinary stop, forced launcher death, runtime crash,
  startup failure, and repeated lifecycle stress (at least 25 cycles): no owned
  process remains after the ten-second cleanup deadline. Test the spawn/ownership
  race; suspended-then-assigned alone does not cover a launcher dying in between.
- Any ownership-setup failure must fail closed. No name-based or substring-based
  bulk termination. Use exact process identity plus creation time or owned handles.
- Worker timeout, memory-budget breach, invalid protocol and crash: bounded
  recovery or explicit degraded/circuit-open state, never false HEALTHY. Preserve
  config, never blindly replay a possibly-invoked action, and prevent restart loops.
- Stop/install/upgrade/rollback must preserve machine-specific settings, leave one
  verified launcher/runtime pair, and not interrupt unrelated processes. Back up
  runtime, bridge config/state, relevant Codex config, task XML and hashes first.
- Configuration tests must cover backups, mutual exclusion, failed/contended
  writes, preservation of unrelated entries and concurrent-edit detection.

## Sustained candidate gate

At least one host must complete **two continuous hours** of representative
candidate operation against one unchanged source/artifact manifest. Record host
session availability, actual scan/reconcile activity and workload limitations.
A suspended machine or mostly unexercised observer is not representative.

Use a ten-minute warm-up and samples at most 30 seconds apart (at least 200 usable
post-warm-up samples). Report least-squares Private Bytes growth slope per process
and aggregate, peaks, final/initial windows, worker generations and handle trends.
For the normal (not fault-injected) run:

- aggregate bridge-owned steady Private Bytes peak <= 512 MiB;
- post-warm-up aggregate slope <= 0.25 MiB/minute and final 15-minute median no
  more than 16 MiB above the preceding 15-minute median;
- aggregate handles peak <= 2,000 and post-warm-up slope <= 0.2 handles/minute;
- no normal-load budget recycle, unexplained worker generation change, residual
  child, duplicate bridge, damaged config, unbounded scan, or false health result.

Report old/new workload comparison separately. An old bounded abort is a result,
not a successful old baseline. Two hours is a minimum observation window, not a
proof of permanent stability. Any unfinished sustained test remains PENDING and
blocks release/full rollout; never extrapolate two points or seconds into hours.

## Release and rollout gate

Publish v0.2.2 only after candidate gates pass and after rechecking tag absence.
Require an identified source commit, reviewed diff, version/changelog/security
documentation, artifact manifest with hashes, and traceable build inputs.
Use the same accepted artifact on all three hosts; do not rebuild separately and
call differing binaries the same verified artifact.

Order: source host, Local, T113; maintain only one host at a time and keep other
connections available for recovery. Verify running version/manifest, unique
launcher/runtime, new creation times, functional logs and repeated resource
samples on each host. Preserve local paths/roots/settings; do not copy another
host's configuration. A failure rolls back that host and stops rollout.

## Evidence and delivery

Keep raw host-specific logs and backups local (not in a public release). Deliver
confirmed root causes separately from hypotheses, source changes, test receipts,
sustained results, release identity, actual three-host deployment state, rollback
locations and remaining blockers. No local Codex inference is needed by default.
