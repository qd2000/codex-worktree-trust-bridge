# v0.2.2 Git/reconcile acceptance contract

Status: **frozen before the Git execution changes in this work stage**.
This contract is narrower than the overall v0.2.2 acceptance contract and does
not by itself authorize release or deployment.

## Execution bounds

- Every Git child is created with an explicit timeout, stdout byte limit, stderr
  byte limit, process-count limit and memory budget. Defaults are conservative
  and configurable only inside bounded ranges.
- Git and any descendants are owned as one process group. Timeout, output-limit,
  memory-limit, abnormal exit or authority shutdown must leave no owned child.
- Output is read as bounded bytes. No `ReadToEnd`, unbounded line reader or
  unbounded string builder is permitted in the long-lived authority runtime.
- Timeout starts before process creation and covers startup, execution, output
  draining and verified cleanup. Cleanup has its own finite deadline.
- A command returning more output than permitted is a rejected command, not
  truncated success. Error diagnostics are separately bounded.
- Missing, malformed, non-UTF-8 or path-escaping Git output fails closed.

## Reconcile semantics

- A reconcile run has an end-to-end deadline and finite repository, directory,
  worktree and Git-command budgets. Discovery may not expand without bounds.
- Any timeout, output breach, process cleanup uncertainty or repository-budget
  breach makes that reconcile unsuccessful. The previous managed trust state is
  preserved; a partial discovery result must not prune or rewrite trust state.
- A normal non-zero Git result for one invalid/stale candidate may be recorded as
  a bounded skipped candidate only where the caller explicitly treats it as
  validation failure. Infrastructure failures are never converted into success.
- Health reports command counts, timeout/output failures, current active count,
  last duration, reconcile duration and last failure. Failed or incomplete
  reconcile cannot report `healthy=true` merely because UIA is healthy.
- Reconcile remains single-writer and cannot overlap itself.

## Isolated functional tests

The controlled Git fixture must cover:

1. normal root/worktree discovery;
2. path containing spaces and bounded UTF-8 output;
3. hanging Git process and hanging descendant cleanup;
4. stdout and stderr limit breaches;
5. non-zero exit with bounded diagnostic;
6. malformed/non-UTF-8 output;
7. excessive repository/worktree/directory budgets;
8. failed reconcile preserving the exact prior managed state and config;
9. health becoming degraded on infrastructure failure and recovering only after
   a complete successful reconcile;
10. repeated successful reconcile with no child, handle or memory accumulation.

All fixtures use an isolated profile and allowed root. They must not query or
write the production Codex configuration, task or project roots.

## Resource experiment

- Run at least 100 controlled successful reconciles after warm-up, plus bounded
  fault cases. Record authority Private Bytes, Working Set, managed heap, handle
  count, Git command count, reconcile count, durations and all child identities.
- Use at least 30 post-warm-up resource samples. Private Bytes and handle
  least-squares slopes must be reported rather than inferred from first/last.
- For the isolated run, authority Private Bytes peak must be <= 256 MiB, handles
  peak <= 1,000, post-warm-up Private Bytes slope <= 0.25 MiB/minute and handle
  slope <= 0.2/minute. No owned Git process may remain after any case.
- A short isolated resource pass is a final-candidate prerequisite, not a
  substitute for the representative two-hour qdspc gray run.

## Candidate freeze and rollout

- After this implementation, rebuild from a clean commit and run the complete
  suite. Freeze exactly one artifact directory and record its manifest SHA-256.
- No source, script, binary, configuration default or workflow may change after
  freeze without invalidating the candidate and repeating the suite.
- qdspc is the only first canary. Its production-specific backup must be created
  immediately before deployment. Failure triggers exact rollback and stops the
  rollout.
- qdspc must complete the frozen overall two-hour representative gray gate before
  Local and T113 are touched. All hosts receive byte-identical artifacts.
- Local is second and T113 third. A failure on one host rolls back only that host
  and prevents expansion. Machine-specific roots/configuration are preserved.
- GitHub tag/release publication is not implied by deployment and remains closed
  unless separately accepted.
