## Implementation delivered

- Launcher/runtime ownership is established at process creation with a
  kill-on-close Windows Job Object. Stop, crash, upgrade and rollback do not rely
  on process-name or command-line-substring termination.
- The long-lived authority runtime performs path policy, Git/reconcile,
  configuration and durable authorization-state work. UI Automation runs in an
  isolated MTA worker with finite traversal, message, timeout, memory and process
  budgets.
- UI actions use fresh dialog/path/control validation and single-use tokens. A
  lost or uncertain response is durably recorded and is not replayed after worker
  recovery.
- Git execution is Job-owned and bounded by time, output bytes, strict UTF-8,
  memory, active process count and cleanup deadlines. Reconcile additionally has
  end-to-end directory, repository, worktree and command budgets.
- Installation and rollback use exact process identity, hash-verified host-local
  backups, same-volume staged replacement, machine-specific configuration
  preservation and automatic rollback on failed readiness.

## Complete-suite and maintenance evidence

The final clean candidate passed the 14-group bounded suite. Coverage included:

- lifecycle and pre-resume ownership races;
- duplicate launch rejection and residual-process cleanup;
- controlled UI scanning, stale token and changed-dialog rejection;
- timeout, memory, protocol, pipe-peer and crash containment;
- durable uncertain-action recovery and configuration conflict handling;
- bounded Git output, timeout, memory, descendant and malformed-output cases;
- repeated reconcile resource trends and discovery budgets;
- corrupt artifact rejection, fresh install, upgrade, explicit rollback,
  failed-start rollback and failed-uninstall rollback;
- candidate freeze, gray-authorization validation and live UI cadence.

All bounded test jobs reported verified cleanup. Failed pre-release iterations
were retained as separate evidence and were not relabeled as passing runs.

## Post-gray containment observation

After the two-hour gate, the canary encountered one real UIA provider traversal
that escaped the requested subtree. The worker rejected the scan, the authority
entered a short degraded state, recycled only the UI worker and recovered to
`HEALTHY` without restarting the Launcher/Runtime, replaying authorization or
losing configuration. This is expected containment behavior, not evidence that
all third-party UIA provider behavior is intrinsically defect-free.

## Rollback and support boundary

Each production host retains a backup bound to its installation receipt. A
rollback verifies the receipt, backup hashes, exact running identity and
machine-local configuration before restoring files and the Scheduled Task.

The release demonstrates bounded operation under the accepted workload; it does
not claim that future Codex Desktop, Windows, Git or accessibility-provider
changes can never require an adapter or limit update. The bridge remains
fail-closed when path, process, dialog, action or cleanup identity is uncertain.
